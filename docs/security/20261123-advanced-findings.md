## Additional related gaps closed

Stripe customer reuse is bound to verified user UUID metadata; an unverified email claim can no longer reassign another customer's metadata. Both `has_active_subscription` overloads now use invoker/RLS privileges. Security audit RPCs remain public intentionally: they expose booleans for deployment checks, not customer records or credentials.

## Validation and reusable workflow

- `scripts/test-advanced-security.sql`: synthetic fixtures, negative/positive role probes, always rolled back. Tested together with the migration before applying it.
- `scripts/test-security-boundaries.sql`: previous role regression suite; updated expected report count to 8.
- `npm run check:rpc-security`: 8 nonempty named checks, including 29 service-only RPC signatures, account read isolation, verified telemetry and customization ownership.
- `tests/security-findings.test.ts`: managed cron, capability integrity, exact product quantities and redirect boundaries.
- `tests/diagnosis-persistence.test.ts`: bundled real server round trip against a stub database; verifies signed external reference but raw UUID foreign keys and cross-owner denial.
- Existing `database-security-review` skill extended with the proven advanced-review method.

Jev 1.14.0 advisory review flagged the initial anonymous UUID-as-capability boundary (gap probability 0.83). That design was replaced with HMAC references and tested. It supported separating verified trust from self-reported telemetry (0.82); classification evidence was less decisive (0.61), so the integrated implementation explicitly separates public metadata in its own column. Jev is not an approval or security gate.

Anonymous exams created before this change must be restarted; plain UUIDs no longer authorize anonymous history. Rotating the server signing credential invalidates anonymous capabilities. No existing user records are deleted. Historical unverified telemetry remains stored but no longer increases verified trust.
